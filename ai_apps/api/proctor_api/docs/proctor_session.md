# proctor_session.py Documentation

## Overview
`proctor_session.py` implements the API endpoints for managing **Proctor Session** records. It provides utilities for synchronising session metrics, deleting sessions, listing sessions with pagination, retrieving detailed session analytics, and serving evidence files from SharePoint.

## Key Functions
- **`sync_session_metrics(session_id: str)`** – Calculates analytics (total events, critical events, penalty points, trust score, risk level) from child events in the associated `Proctor Event` and updates the `Proctor Session` document.
- **`delete_session(session_name: str)`** – Deletes a `Proctor Session` document after validating the input.
- **`list_sessions(filters: str = "{}", page: int = 1, limit: int = 20)`** – Returns a paginated list of sessions with optional JSON filters.
- **`get_session_details(session_id: str)`** – Retrieves comprehensive analytics for a single session, including events, evidence, and violation counts.
- **`get_evidence_file(evidence_id: str)`** – Generates an authenticated redirect URL for a SharePoint‑hosted evidence file, handling token‑based access and fallback URLs.

## Workflow Highlights
1. **Metric Synchronisation** – `sync_session_metrics` queries the `Proctor Event` child table, aggregates severity and penalty data, derives a trust score (`100 - total_penalty_points`), and determines a risk band via the `RuleEngine`.
2. **Session Deletion** – Validates the session name, loads the document, calls `delete()`, and commits the transaction.
3. **Listing & Pagination** – Parses JSON filter strings, computes offsets, and returns total counts along with pagination metadata.
4. **Detailed Retrieval** – Gathers session header, events, evidence, and computes violation statistics while mapping evidence URLs to a proxy endpoint for secure streaming.
5. **Evidence Access** – Constructs a Microsoft Graph URL to fetch a direct download link, falls back to stored URLs, and issues a `302` redirect.

## Security Considerations
- All endpoints are `@frappe.whitelist(allow_guest=True)` but enforce strict validation (e.g., required parameters, existence checks) and raise `ValidationError` on malformed input.
- Database writes occur within transactions; failures trigger rollbacks to maintain consistency.
- `get_evidence_file` limits file size indirectly via SharePoint and sanitises the SharePoint path using URL encoding to prevent injection attacks.
- Logging uses `frappe.log_error` to capture stack traces without exposing sensitive payloads.
- Access to SharePoint is performed with a bearer token from a secure client configuration.
