# rule_engine.md

## Overview
`rule_engine.py` implements a lightweight, thread‑safe rule engine that evaluates **Proctor Rule** definitions against incoming events. It provides:

- Data classes for **Event**, **Condition**, **Rule**, and **Violation**.
- An in‑memory **SessionStore** backed by `frappe.cache()` for per‑session state (rule fire timestamps, accumulated durations, occurrence counts, violations, and trust scores).
- The **RuleEngine** class which loads rules (from a JSON file or the `Proctor Rule` DocType), processes events, calculates penalties, and derives a trust score and risk band.
- Public whitelisted API `get_trust_score` for retrieving a session’s trust score.

The engine is used by other API endpoints (e.g., `evaluate_event`) to assess violations in real‑time and update session metrics.

## Key Components

| Component | Purpose |
|-----------|---------|
| **Event** | Simple representation of an incoming detection event (`event_type`, `payload`, `timestamp_ms`). |
| **Condition** | Encapsulates the rule’s logical condition (type, threshold, window, count). |
| **Rule** | Holds rule metadata (ID, event type, activation flag, condition, severity, penalty, cooldown). |
| **Violation** | Records a rule breach (rule ID, severity, penalty, timestamp, optional details). |
| **SessionStore** | Manages per‑session state via `frappe.cache()`: rule state, violation list, and score. |
| **RuleEngine** | Core engine: loads rules, evaluates events, records violations, updates scores, provides risk band mapping. |

## Workflow Highlights
1. **Rule Loading** – `RuleEngine.load_rules(path=None)` loads from a supplied JSON file or falls back to `frappe.get_all("Proctor Rule", fields="*")`. Rules are cached after the first load.
2. **Event Processing** – `process_event(session_id, event)` iterates over enabled rules matching the event type, checks cooldowns, evaluates conditions via `_evaluate_condition`, applies correlation logic to uplift severity, records violations, and updates per‑rule state.
3. **Scoring** – `SessionStore.record_violation` deducts the violation penalty from the session’s score (capped at 0). `get_score` returns the cached score or reconstructs it from DB violations if the cache is empty.
4. **Risk Band** – `RuleEngine.get_risk_band(score)` maps a trust score to a textual risk band (`LOW`, `MEDIUM`, `HIGH`, `CRITICAL`).
5. **Public API** – `get_trust_score(session_name)` creates a temporary engine, loads rules, and returns the current trust score for the session.

## Security Considerations
- **Input Validation** – `process_event` validates the `session_id` and ensures the event payload conforms to expected structure before evaluation.
- **Cache Isolation** – Session state is namespaced (`proctor:{session_id}:{suffix}`) to prevent cross‑session data leakage.
- **Error Handling** – All external calls (e.g., rule loading, DB access) are wrapped in try/except blocks with `frappe.log_error` for auditability while exposing generic validation errors to callers.
- **Access Control** – The only public endpoint (`get_trust_score`) is whitelisted for guest access; consider restricting it to internal services in production.
- **Rate Limiting** – The engine itself does not impose rate limits; throttling should be applied at the API layer (e.g., via Frappe rate‑limit hooks) to mitigate abuse.
